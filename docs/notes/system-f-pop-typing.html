Plain Old System F #

I have been recently reading Lightweight Linear Types in System F∘F^{\circ}F∘ among other papers which describe ways to incorporate linear types into their type systems. This one adds linear types to System-F. To those familiar with the simply typed lambda calculus, the following terms are canonical:

In each case, the individual terms have different types but the shape of the result is the same:

  • for the first, it’s a term of the same type as the input
  • for the second, it’s the first input term and it’s type
  • for the third, it’s a the result of the composition of two functions where one takes the output of another; the output type is that of the first function (f)

Taking the first lambda term and plugging in any type for a variable would univeralize the type. Mathematically: ∀τ.λx:τ. x \forall \tau. \lambda x{:}\tau.\,x ∀τ.λx:τ.x

encompasses any input type for the term x in the entire lambda expression. This is what System-F does.

F to F-pop #

The new idea in the paper is to bring in linear types via kinds.

I should write an entirely new note on kinds but for our purpose here, simply put, a kind system classifies types.

  • For simple types that can be constructed without the input of any other types e.g. Nat, Bool, the kind is ⋆\star⋆ .
  • A type constructor that takes one input type
    • In OCaml, a type constructor for constructing lists that takes in a type, say ’a and kind ⋆\star⋆ , to construct a list (of type ’a list and kind ⋆\star⋆ ) has kind ⋆→⋆\star \to \star⋆→⋆ .
  • For a function type is of α→β\alpha \to \betaα→β where α\alphaα is the input type and β\betaβ is the output type.
    • When the function is applied to a value of type α\alphaα (kind ⋆\star⋆ ), the result is of type β\betaβ and kind ⋆\star⋆ .
    • For the function constructor itself of type α→β\alpha \to \betaα→β , the kind is a constructor that first takes in a type α\alphaα (kind ⋆\star⋆ ) to return another constructor that takes in a type β\betaβ (again kind ⋆\star⋆ ) to finally return a type of kind ⋆\star⋆ . So the kind for the entire constructor is ⋆→⋆→⋆\star \to \star \to \star⋆→⋆→⋆

In F∘F^{\circ}F∘ , there are two kinds instead of the one base kind in System-F. The second kind is:

∘\circ∘

that denotes linearity. Linear types encompass values that are consumed only once i.e. used only once in a computation. (I should also write another note/post on sub-structural types of which linear types are an example.)

The kind ⋆\star⋆ continues to denote types that are not linear.

The sets of types and kinds now are: τ::=α∣τ1→τ2∣∀α.τκ::=⋆∣∘ \tau ::= \alpha \mid \tau_1 \to \tau_2 \mid \forall\alpha.\tau \qquad \kappa ::= \star \mid \circ τ::=α∣τ1​→τ2​∣∀α.τκ::=⋆∣∘

Since the context is constructed as a set of variable and types, let’s perform a small transformation to its form. The set of all types in a context can be considered as a set with two sorts:

Γtypes::={(τ:⋆),(τ:∘)} \Gamma^{types} ::= \{ (\tau {:} \star), (\tau {:} \circ) \} Γtypes::={(τ:⋆),(τ:∘)}

With variables having type τ\tauτ and kind κ\kappaκ , the set of variables can be binned into the two sorts as:

Γvars::={(x:τ⋆),(x:τ∘)} \Gamma^{vars} ::= \{ (x {:} \tau^{\star}), (x {:} \tau^{\circ}) \} Γvars::={(x:τ⋆),(x:τ∘)}

Now the context is: Γ::=⋅∣(Γtypes+Γvars)which can be rewritten asΓ::=⋅∣{(τ:⋆),(τ:∘),(x:τ⋆),(x:τ∘)} \begin{aligned} \Gamma ::= \cdot \mid (\Gamma^{types} + \Gamma^{vars}) \\ \text{which can be rewritten as} \\ \Gamma ::= \cdot \mid \{ (\tau {:} \star), (\tau {:} \circ), (x {:} \tau^{\star}), (x {:} \tau^{\circ}) \} \end{aligned} Γ::=⋅∣(Γtypes+Γvars)which can be rewritten asΓ::=⋅∣{(τ:⋆),(τ:∘),(x:τ⋆),(x:τ∘)}​

The core piece to start with: term abstractions #

Abstractions over terms (variables) are functions of the following type where κ1\kappa_1κ1​ , κ2\kappa_2κ2​ both can be ⋆\star⋆ or ∘\circ∘ : τ1:κ1→τ2:κ2 \tau_1 {:} \kappa_1 \to \tau_2 {:} \kappa_2 τ1​:κ1​→τ2​:κ2​

In System-F-pop, every type has a kind including function types which can be marked with either kind as:

τ1:κ1→⋆τ2:κ2 \tau_1 {:} \kappa_1 \xrightarrow{\star} \tau_2 {:} \kappa_2 τ1​:κ1​⋆​τ2​:κ2​

denotes a function that can be called any number of times, while

denotes one which can be called only once, irrespective of what kinds both types τ1\tau_1τ1​ , τ2\tau_2τ2​ are.

In each of the four instances for the T-Abs rule, the expression abstracted over can be linear or unrestricted. If the bound variable is linear (instances 3 and 4), it will only be used once within the lambda term. But the most important thing to note is that the kind of the function type is independent of that of the bound variable.

Generalizing the kind of the bound variable:

Γ,x:τ1κ1⊢e:τ2κ2κ1,κ2,κ3:=⋆∣∘Γ⊢λκ3x:τ1. e:τ1→κ3τ2 \dfrac{\Gamma, x{:}\tau_1^{\kappa_1} \vdash e : \tau_2^{\kappa_2} \qquad \kappa_1, \kappa_2, \kappa_3 := \star \mid \circ}{\Gamma \vdash \lambda^{\kappa_3} x{:}\tau_1.\,e : \tau_1 \xrightarrow{\kappa_3} \tau_2} Γ⊢λκ3​x:τ1​.e:τ1​κ3​​τ2​Γ,x:τ1κ1​​⊢e:τ2κ2​​κ1​,κ2​,κ3​:=⋆∣∘​

Do note that the κ3\kappa_3κ3​ over the symbol for λ\lambdaλ is the same κ3\kappa_3κ3​ for the function type and denotes that the whole lambda term of function type τ1→τ2\tau_1 \to \tau_2τ1​→τ2​ has kind κ3\kappa_3κ3​ . Now if kinds κ1\kappa_1κ1​ and κ2\kappa_2κ2​ are completely independent of kind κ3\kappa_3κ3​ , or in other words have no bearing on the kind determined for κ3\kappa_3κ3​ , then what other factor does?

The answer is something outside of the lambda term itself. This makes the lambda a closure that captures some value that is (obviously) not xxx and not bound in eee . If a term or a value captured from outside λ\lambdaλ is linear, then the closure formed by the lambda term capturing such a value is also linear. This means that having a captured linear value makes the lambda term be used only once without any consideration of what the kinds for the bound variable and expression abstracted are. If a term or a value captured from the surrounding scope is unrestricted, then the closure can either be linear or unrestricted.

Term Applications: The T-App rule #

In System-F, the rule for term applications is: Γ⊢e1:τ1→κ1τ2Γ⊢e2:τ1κ2κ1,κ2,κ3:=⋆∣∘Γ⊢e1 e2:τ2κ3 \dfrac{\Gamma \vdash e_1 : \tau_1 \xrightarrow{\kappa_1} \tau_2 \qquad \Gamma \vdash e_2 : \tau_1^{\kappa_2} \qquad \kappa_1,\kappa_2,\kappa_3 := \star \mid \circ}{\Gamma \vdash e_1\ e_2 : \tau_2^{\kappa_3}} Γ⊢e1​ e2​:τ2κ3​​Γ⊢e1​:τ1​κ1​​τ2​Γ⊢e2​:τ1κ2​​κ1​,κ2​,κ3​:=⋆∣∘​

This rule is the obverse of T-Abs in that κ1\kappa_1κ1​ here is the kind of a lambda term. Since κ1\kappa_1κ1​ was determined by capturing of values by the lambda term, κ2\kappa_2κ2​ need not be the same as κ1\kappa_1κ1​ at all. For the rule to apply, the types τ1\tau_1τ1​ in e1e_1e1​ and e2e_2e2​ should match. The kind of the result of the application, again, can be either i.e. whichever value for kind satisfies all other typing constraints in the program.

then:

Γ;Δ⊢e1:τ1→κ1τ2Γ;Δ⊢e2:τ1κ2... \dfrac{\Gamma;\Delta \vdash e_1 : \tau_1 \xrightarrow{\kappa_1} \tau_2 \qquad \Gamma;\Delta \vdash e_2 : \tau_1^{\kappa_2} \qquad}{\text{...}} ...Γ;Δ⊢e1​:τ1​κ1​​τ2​Γ;Δ⊢e2​:τ1κ2​​​

to give: Γ;Δ⊢e1:τ1→κ1τ2Γ;Δ⊢e2:τ1κ2Γ;Δ⊢e1 e2:τ2κ3 \dfrac{\Gamma;\Delta \vdash e_1 : \tau_1 \xrightarrow{\kappa_1} \tau_2 \qquad \Gamma;\Delta \vdash e_2 : \tau_1^{\kappa_2} \qquad}{\Gamma;\Delta \vdash e_1\ e_2 : \tau_2^{\kappa_3}} Γ;Δ⊢e1​ e2​:τ2κ3​​Γ;Δ⊢e1​:τ1​κ1​​τ2​Γ;Δ⊢e2​:τ1κ2​​​

But the above isn’t quite right. Because the linear contexts being the same for all terms in the premises and the conclusions implies that all the terms are type checked for the same set of linear variables. A variable captured within e1e_1e1​ will be eventually used within e1e_1e1​ exclusively. The three new/updated rules, VarAdd-Lin, VarAdd-Un and T-Abs make System-F-pop’s type system closer to being correct and complete. But when you look over all the rules, there’s one that involves kinds of both types without involving the two contexts Δ\DeltaΔ and Γ\GammaΓ .

That rule is T-Var where x is type checked to type τ\tauτ and either kind, linear or unrestricted. But notice that the linear context Δ\DeltaΔ is missing from the rule.

T-UnrestrictVar

When the kind of xxx is ⋆\star⋆ , xxx can only be a member of the unrestricted context Γ\GammaΓ :

x:τ⋆∈ΓΔ=?Γ;Δ⊢x:τ⋆ \dfrac{x{:}\tau^\star \in \Gamma \qquad \Delta = ?}{\Gamma;\Delta \vdash x : \tau^\star} Γ;Δ⊢x:τ⋆x:τ⋆∈ΓΔ=?​

I had trouble thinking of what Δ\DeltaΔ would look like. The clue came from the Delta-Empty, Delta-Left, Delta-Right rules.

A Δ\DeltaΔ context can be constructed from disjoint subsets. If a variable of kind ⋆\star⋆ is in Γ\GammaΓ , there is no linear set to construct or put this variable into. So Δ\DeltaΔ can be simply empty here as:

x:τ⋆∈ΓΔ=⋅Γ;Δ⊢x:τ⋆ \dfrac{x{:}\tau^\star \in \Gamma \qquad \Delta = \cdot}{\Gamma;\Delta \vdash x : \tau^\star} Γ;Δ⊢x:τ⋆x:τ⋆∈ΓΔ=⋅​

The obverse happens when the variable is linear.

T-LinVar

Now the variable with linear kind ∘\circ∘ can be put into the smallest set Δx\Delta_xΔx​ . The typing rule is simply:

x:τ∘=ΔxΓ;Δx⊢x:τ∘ \dfrac{x{:}\tau^\circ = \Delta_x}{\Gamma;\Delta_x \vdash x : \tau^\circ} Γ;Δx​⊢x:τ∘x:τ∘=Δx​​

When several linear variables (terms) are to be put together into one linear context, say yyy , zzz , …, the disjoint union of all the subsets, Δy\Delta_yΔy​ , Δz\Delta_zΔz​ , … make up Δ\DeltaΔ .
